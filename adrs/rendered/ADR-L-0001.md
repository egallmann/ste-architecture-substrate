# ADR-L-0001: Architecture Substrate Repository Scope

**Status:** proposed  
**Created:** 2026-05-02  
**Authors:** Erik Gallmann  
**Domains:** architecture, infrastructure-as-code, governance  





---

## Context

The STE ecosystem needs a machine-first repository of reusable architecture artifacts
that accelerate system design and reduce repeated architectural decision-making.

Current state: Engineers and AI systems start from scratch for each architecture,
leading to repeated discovery, inconsistent designs, lossy reasoning, and slow iteration.

Desired state: Architecture starts from prebuilt, structured, machine-readable artifacts
(seeds, building blocks, primitives) that encode both structure (IaC) and intent
(mutation rules, ADR context).

This ADR defines the scope and boundaries of the ste-architecture-substrate repository
as the foundational layer from which architectures are formed.


## Capabilities

### CAP-0001: Artifact Storage

Store architecture seeds, building block bundles, and primitive blocks with associated metadata

### CAP-0002: Artifact Structuring

Define and maintain schemas for artifact types and discovery surfaces

### CAP-0003: Mutation Rule Definition

Encode machine-readable constraints on artifact evolution (immutable, mutable, conditional)


## Architectural Boundaries

### BOUND-0001: Included Responsibilities

**Description:**
Artifact storage, artifact structuring, mutation rule definition, discovery
surface provision


**Rationale:**
These responsibilities define substrate's core value: providing structured, reusable
architecture artifacts with normative guidance


### BOUND-0002: Excluded Responsibilities

**Description:**
Validation logic, enforcement behavior, runtime execution, policy decision-making,
projection logic (consuming systems own these)


**Rationale:**
Substrate is a storage layer, not an enforcement or execution layer; clear boundaries
prevent scope creep and maintain separation of concerns



## Interaction Contracts

### CONTRACT-0001

**Parties:** ste-architecture-substrate, adr-architecture-kit, conversation engines, ste-runtime  
**Protocol:** File-based artifact retrieval with discovery bundles

**Guarantees:**
Artifact structure is deterministic and projection-ready. Discovery bundles
provide complete artifact metadata. IaC artifacts are structurally valid per
technology schema.


### CONTRACT-0002

**Parties:** ste-architecture-substrate, consuming systems  
**Protocol:** Read-only file access to conventional directory structure

**Guarantees:**
Conventional paths are stable across versions. Discovery bundles are machine-readable
YAML. Sibling repo resolution follows STE workspace patterns.

## Decisions

### DEC-0001: ste-architecture-substrate is a storage and structuring system for architecture
artifacts, NOT a validation or enforcement framework.


**Rationale:**
Separation of concerns: substrate provides artifacts, consuming systems (adr-kit
extensions, conversation engines, ste-runtime) perform projection, interpretation,
validation, and enforcement. This preserves the Ulysses contract model where
constraints guide by default but can be overridden with explicit intent.





### DEC-0002: Core artifact types are seeds, building block bundles, and primitive blocks.

**Rationale:**
Seeds provide complete starting architectures, building blocks provide reusable
components, and primitive blocks provide low-level fallback constructs. This
three-tier model balances high-level acceleration (seeds) with granular composition
(blocks and primitives).





### DEC-0003: Substrate artifacts follow the Ulysses contract model: pre-committed intent,
normative but non-enforcing, compliance by default, deviation allowed, enforcement
external to substrate.


**Rationale:**
Architects and AI systems should be guided toward compliant designs by default,
but must retain the ability to deviate with explicit intent. Substrate encodes
normative guidance (mutation rules) without blocking override. External systems
(CI, CloudFormation hooks, SCPs) optionally enforce constraints.





### DEC-0004: Projection vs interpretation invariant: structure is deterministically projected,
intent is interpretively generated.


**Rationale:**
IaC structural elements (CloudFormation templates, Terraform modules) must be
reusable 1:1 without reinterpretation (deterministic projection). Architectural
reasoning (why this structure, what tradeoffs, which alternatives rejected) must
be generated based on system context (interpretive generation). This separation
enables reliable structure reuse while preserving context-specific reasoning.





### DEC-0005: Structural validity invariant: all IaC artifacts MUST be structurally valid
according to their technology's schema.


**Rationale:**
Valid IaC enables deterministic 1:1 projection into consuming systems without
correction. CloudFormation templates must conform to CFN schema, Terraform modules
must be valid HCL. Structural validity is a pre-condition for substrate artifacts,
not enforced by substrate at runtime.





### DEC-0006: Substrate does not perform validation, enforcement, or runtime execution.

**Rationale:**
Substrate is a storage and structuring layer. Validation (schema conformance,
constraint checking), enforcement (blocking non-compliant changes), and runtime
execution (deploying IaC, running governance rules) are responsibilities of
consuming systems. This maintains clear boundaries and prevents scope creep.





### DEC-0007: Alternatives considered and rejected: template library (no mutation rules/normative
guidance), policy engine (enforcement contradicts Ulysses contract), validation
framework (substrate provides structure, consumers validate).


**Rationale:**
Template library: insufficient - provides structure but no normative guidance
on evolution. Policy engine: wrong model - enforcement contradicts normative-but-overridable
Ulysses contract. Validation framework: wrong responsibility - substrate provides
artifacts, consuming systems validate. Repository model with guided artifacts
selected to balance structure provision with guidance without enforcement.
